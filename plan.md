## Architecture and deployment

Keep the existing React, TypeScript, Vite and Tailwind codebase as the basis for the storefront. Add a second, separately built React/Tailwind admin front end. Build both as independent static output folders. Place the shared HTTP API in Netlify Functions, with `/api/*` routes for the public menu/order flow and protected admin operations. Host the storefront and its functions together as the primary Netlify site. Host the admin output as a second Netlify site, also on Netlify. Use a same-origin Netlify rewrite on the admin site that proxies `/api/*` to the primary site's API. The browser therefore talks to its own Netlify origin; the API validates expected storefront/admin origins and the owner session. The admin app never receives database credentials.

Use Netlify Database (managed Postgres) only in the primary/API site, via `@netlify/database` and its supported `getDatabase()` access. Put additive SQL migrations under the Netlify Database migration directory and never use Drizzle `push` or destructive schema reset. Use parameterized SQL, transactions for order creation and line-item snapshots, and server-side Zod validation. Recheck published product state, verified pricing, slot availability, fulfillment mode, and server-calculated totals within the transaction. Persist products, categories, line-item snapshots, orders, order status transitions, business settings, and date/time availability. Idempotency keys prevent duplicate order writes. Store customer details minimally and disclose their use for handling the order.

Secure admin login using environment-managed owner credentials on the API site: owner email/username, a password hash generated by a setup script, and a strong session-signing secret. Use a short-lived, HttpOnly, Secure, SameSite cookie on the admin Netlify origin, signed sessions, `Origin` validation/CSRF protection, rate-limited login, generic auth failures, and protected admin operations. Do not ship a default password, include private credentials in static output, or bypass authentication in local/production modes. Since the API is proxied from the admin origin, the browser session remains same-origin with the admin site; the API remains the authority for roles and data. All secrets stay in Netlify's server-side environment.

The storefront includes mobile navigation, an editorial hero with illustrative Nigerian food photography (explicitly not represented as the business’s exact plating), verified schedule/status notice, searchable/filterable menu, detail view, cart, customer information, preorder date/time, pickup or delivery, and a structured WhatsApp message. Persist an order only after server-side checks, set its status to awaiting business acceptance, then offer the user a WhatsApp link to send. Clearly state that the request is not accepted until the business confirms it. The admin site provides secure login, product creation/editing with publish/unpublish controls, category creation/rename/archive/restore, currency configuration only after owner confirmation, price/description/availability edits, schedule/time-slot controls, delivery/pickup zones and fees, editable policies, order search/detail/status management, and public business settings. Category archival is reversible and blocked while current products still reference the category; historical order and product records are not physically deleted.

Provide initial HTML metadata, page content, accessible semantics and keyboard paths, visible focus, reduced-motion support, responsive layouts, optimized/lazy-loaded images, SEO metadata, sitemap/robots and non-PII analytics readiness. Canonical public URLs remain unconfigured/omitted until the owner supplies final domains. Protect `/admin`/admin site routes from indexing. Handle offline/loading/failure/empty states honestly. Include a Netlify runbook covering separate site creation, API-first deployment, admin proxy origin configuration, Node/CLI requirements, migrations, owner secrets, data review and production gates. Netlify’s current Database guide requires a credit-based Netlify plan for active databases; disclose that prerequisite and do not claim the database is live until the user initializes it in their Netlify team. The official guides are [Netlify Drop](https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/), [Functions](https://docs.netlify.com/build/functions/get-started/), [Netlify Database](https://docs.netlify.com/build/data-and-storage/netlify-database/), and [Database setup and migration workflow](https://www.netlify.com/knowledge-base/how-to-add-a-postgres-database-to-a-netlify-app/).

- `netlify.toml`: primary storefront + Functions configuration; `netlify.admin.toml`: independent static admin build/security configuration.
- `dist/storefront/` and `dist/admin/`: static output directories created by the two-site build; the admin proxy is generated only with the real API origin.
- `README-NETLIFY.md`: Netlify sites, database setup, secrets, API proxy, owner review gates, and launch verification; `README.md`: project entry point.
- `plan.md` and `TODO.md`: accepted implementation approach and outcome-based progress.

## Design system

Three visual approaches: sunlit food-journal editorial (0.07), contemporary market-stall minimalism (0.05), and polished supper-club warmth (0.03). Choose **sunlit food-journal editorial**: calm editorial layout with generous cream space, warm terracotta, forest-green anchors, dark-brown type, and one strong Nigerian food-photography hero. Use only real food imagery that is clearly illustrative unless the owner provides actual product photography.

Principles: warmth without clutter, trust before conversion, legible preorder timing, and genuine editable business information. Cream softens the page, terracotta invites action, forest green anchors navigation/availability, dark brown supports comfortable reading, and white provides clean surfaces. The layout is editorial and asymmetrical on desktop, naturally flowing on mobile with scheduling and cart actions thumb-reachable. Signature motifs are a fine plate-rim line, a small botanical accent, and terracotta preorder pills. Interaction is immediate, reversible, and explicit about fees/availability. Motion is subtle, brief and reduced-motion aware, with no parallax or scroll-jacking. Use Fraunces for expressive headings and DM Sans for body/UI, with comfortable mobile line-height.

Brand essence: a considered preorder-food storefront for Port Harcourt; warm, clear, dependable. Brand voice is direct and hospitable: “A good meal is worth planning for.” “Choose a date, send your request, and we’ll confirm it with you on WhatsApp.” The website can use a proposed plate-and-leaf line mark and typeset wordmark, but must not present it as the business’s official logo. Signature brand color: terracotta `#C65D35`.

## Verified Netlify database deployment details

Netlify Database is managed Postgres. Installing `@netlify/database` is the provisioning signal; `getDatabase()` resolves the correct connection for the current Netlify environment. Schema files belong under `netlify/database/migrations/`, named `<number>_<slug>.sql`; timestamp prefixes are preferred. Netlify applies committed migrations automatically before production/deploy-preview publication; local development requires `netlify database migrations apply`. Use `db.pool` for transactions and release clients in `finally`; the tagged `db.sql` helper does not hold one connection across statements. Preview databases are separate branches, but initially copy production data, so they may contain personal information. Netlify Database requires a credit-based Netlify plan. Source: [Netlify Database guide](https://docs.netlify.com/build/data-and-storage/netlify-database/) and [Netlify Database setup and migration guide](https://www.netlify.com/knowledge-base/how-to-add-a-postgres-database-to-a-netlify-app/).
